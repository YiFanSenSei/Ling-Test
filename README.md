## 一、作品简介

「匠作」是一座可以走进去的中国非物质文化遗产数字展馆。

它不试图做一份资料汇编，而是一次「重新介绍」的尝试：把名录里那些只剩一个名字的手艺，重新讲成有人、有工序、有温度的事。

全站以国家级非物质文化遗产代表性项目为内容，收录 **3,614 条**按申报地区拆分的子项记录，覆盖 **十大类别**、**33 个省级行政区**与 **五批**公布年表。**每一条都建有完整详情页**，转录了官方的项目介绍正文（合计约 249 万字）与国家级代表性传承人档案；站内另为 **4,032 条**传承人档案记录建立了可检索、可逐人翻阅的独立档案页。

> 详情正文已全量补录完成（覆盖率 **3,614 / 3,614 = 100%**）。数据管道、体积方案与后续计划见 [`NOTES.md`](./NOTES.md) 的「当前进度与后续任务」一节。

此外，本站把三门手艺做成了可交互的体验：**苏绣的按图落针、宣纸的捞纸工序、榫卯的咬合**。目的很简单——让「非遗」这两个字从名词变成动词。

### 检索设计

名录与传承人两页的检索都做了**同义词扩展**：官方项目名用的是行业术语，而访客按日常叫法来搜，因此「瓷器」会自动一并联查「瓷」、「丝绸」联查「丝 / 锦 / 绸」、「玉器」联查「玉雕」。实测「瓷器」由 0 条提升到 38 条，「丝绸」由 1 条提升到 59 条，且逐条核对无伪命中。

对于「戏曲」「音乐」这类**指向整个门类**的词，程序不会假装它们能当关键词用，而是识别出来并提示「你要找的是一个门类」，同时给出通往该门类筛选的按钮——把控制权交回访客，而不是丢给他一堆沾边的结果。

### 项目之间的横向关联

名录收录 3,614 条记录，其中 2,569 条与其他记录共享项目编号。本站从编号里找出一条**真实**的关联线索：

官方项目编号形如 `Ⅶ-018_01_320500`，短横线前那段 `Ⅶ-018` 是**项目本身**的编号，后面两段才是批次与地区。把 3,614 条记录按前缀归并，恰好得到 **1,557 个不同的编号**，与官方公布的「国家级代表性项目 1,557 项」完全吻合——说明这两个数字不是两套数据，而是同一份名录的两种粒度。

这也就是项目页「同一项目的其他申报地区」一节的依据：2,569 条记录与其他记录共享编号，分布在 512 个项目里；最多的一组是「剪纸」，共有 56 个申报地区（蔚县剪纸、扬州剪纸、傣族剪纸……）。苏绣一组则能清楚看到无锡精微绣、南通仿真绣、扬州刺绣、常州乱针绣四个地方流派。**每一个项目页都有这一节**（除 1,045 个只申报过一次的项目）。它是本站自己组织的关联，不是官网给的栏目——让每个项目都能横向展开到同源的版本，而不是翻完就到底。

### 关于「看起来重复」

同一项目由多地申报，会拆成多条记录。这本身是官方登记方式，但**若界面不解释，读者只会觉得站点在复读**。本站为此做了三件事：

**一、列表与卡片一律显示申报地区或单位（精确到市/县），不用省级字段。** 这一点是看截图时发现的：剪纸一组里出现了三行完全一样的「剪纸（广东剪纸）· 广东省」，一查并非重复数据——广东剪纸确实由佛山市、汕头市、潮州市分别申报，只是省级字段把它们抹平了。改用精确字段后，全站「看起来重复」的行从 257 行降到 1 行。**同一修正后来才补到名录卡片上**：卡片原先用的仍是省级的 `region`，「苗族古歌」由台江县、黄平县申报的两条记录在列表里就是两张一模一样的卡片——正是「内容重复」观感的直接来源。

**二、卡片底部标注「同项目 N 处申报」。** 全站 512 个项目有多条申报记录（覆盖 2,569 条，最多的一组「剪纸」有 56 处）。标注把「为什么列表里有好几张同名卡片」直接写在卡片上，而不是让访客自己猜是不是抓重了。

**三、详情页正文前说明这份介绍的来历。** 官网为「一个项目」只写一份简介，多申报地区的页面挂的是同一份文字：把 3,614 条记录去掉首行「申报地区或单位：…」并忽略空白后比对，有 **200 组、共 482 条（13.3%）** 正文逐字相同，且**全部落在同一个项目号前缀内**（跨项目重复 0 组）——可见成因单一。因此详情页会在正文前标注：这份介绍是官网为项目 `Ⅰ-001`「苗族古歌」统一撰写的，同项目另有 N 处申报地区沿用同一份文字，本页是其中哪一处的记录。不加这句，访客连点两条同名记录会以为站点在复读；加了之后，它反而成了一条关于「国家级非遗按地区申报」的知识点。

> 回归脚本对第三点做了**正反两条**断言：`#/project/12178`（台江县，正文与黄平县逐字相同）必须出现这句说明；`#/project/12179`（花垣县，官网单独撰写）必须**不出现**。少了反向那条，「说明」有可能被无差别贴到所有页面上而测试照过。

## 三、非自写库及用途声明

按比赛要求逐项注明第三方库的名称与用途：

| 名称 | 性质 | 用途 | 是否影响评分的制作难度 |
|---|---|---|---|
| Vite | 构建工具（开发期） | 模块打包与开发服务器。构建产物为原生 HTML / CSS / JavaScript，运行时**不加载任何框架**。 | 否，仅用于打包，不参与页面呈现 |
| — | 无其他第三方依赖 | 无 UI 组件库、无 CSS 框架、无图标库、无动画库、无外部字体文件。所有图形（纹样、徽记、模拟器画面）均为程序化绘制或内联 SVG。 | — |

**说明**：展馆主体可静态离线运行；在线版另有 Node.js 与 SQLite 作品投稿、审核和作品墙。全部代码由团队手写，未使用任何 UI 框架与预设样式库。Vite 只在开发阶段用于打包，构建产物是 `dist/index.html`（约 1.6 MB，JavaScript、CSS 与名录数据全部内联）外加一个 `dist/data/` 目录，评委双击「打开作品.html」即可运行，无需安装任何依赖、无需联网加载资源。

> 关于这一步为什么必要：Chrome 自 2021 年起禁止 `file://` 页面加载 `<script type="module">`，也禁止其用 `fetch` 读取同目录 JSON（跨源策略，本地页面的 origin 为 `null`）。因此「外链 JS + 外链数据」的常见产物，评委双击后只会停在加载画面上。我们把 JS / CSS / 名录数据全部内联进单个 HTML，并且改成普通 `<script>`（非 module），从根上避免了这两条限制。

> **详情数据是个例外，而且是刻意的**：全量补录后项目详情合计约 9.6 MB，全部内联会让首屏涨到 11 MB 量级。而上面那条限制有个反面——`file://` 禁止的是 `type="module"` 与 `fetch`，**普通 `<script src>` 依然可用**。于是详情被切成 19 个 `detail-N.js` 分片，打开某个项目时才注入它所在的那一片（约 500 KB）；传承人索引同理，只在传承人页按需加载。首屏因此稳定在 1.6 MB，与补录进度无关。此行为已在真实浏览器中以 `file://` 协议完整回归验证：全部路由与三项交互正常，控制台零报错、零网络请求失败。回归脚本里有一条专门的断言：**先取基线（0 条），再打开名录最后一条项目，本次只注入了 14 条**（该分片共 14 条，单片上限 200 条），累计 14 / 3,614——而不是把全量详情一起拉进来。

## 四、界面规格与技术实现

| 项目 | 说明 |
|---|---|
| 界面规格 | **1440 × 900**（比赛要求三选一；已在页面 `<meta name="design-spec">`、页脚与「关于本站」页三处标注） |
| 自适应 | 响应式布局，覆盖 1920 / 1440 / 720 三档及移动端（390）、平板（834）。实测 35 个「规格 × 页面」组合，横向溢出均为 0。 |
| 移动端 | 不只是「不出横向滚动条」——用 CDP 派发**真实触摸事件**逐项实测：三个模拟器都能用手指完成（苏绣落针、宣纸荡帘评分、榫卯把构件沿轴推到位并咬合，咬合后试提还提不动——燕尾防脱），画布上的手势不会劫持页面滚动、画布之外可正常滚动，多点触控不误触；汉堡菜单可点开、可跳转、跳转后不残留滚动锁。可点元素在触摸设备上按 44px 标准放大（用 `@media (pointer: coarse)` 而非宽度断点——触摸笔记本窗口可能很宽，但输入仍是手指）。 |
| 路由方案 | Hash 路由。保证在 `file://` 协议与任意静态托管下均可直接打开、刷新不 404，无需服务器。 |
| 分发形态 | 首屏单文件 HTML（约 1.6 MB，内联全部 JS / CSS 与名录数据）+ `data/` 目录（19 个详情分片与传承人索引，打开对应页面时按需注入）。评委解压后双击 `打开作品.html` 即用，无需服务器、无需联网。 |
| 数据加载 | 名录、统计口径、覆盖率索引、策展名单在构建时内联；项目详情按 200 条一片切成 19 片，传承人索引单独一份，均由运行时以普通 `<script>` 注入。分片只加载一次，同页内不重复请求。内联的小索引里另带两份构建期算好的对照表——「哪些记录共用同一份官方简介」与「哪些项目有多条申报记录」——展示层据此标注来源与徽标，运行时无需再遍历全量数据。 |
| 页面清理 | 路由切换时显式释放上一页的资源（`cancelAnimationFrame` + `removeEventListener`）。实测进出模拟器 1 / 3 / 6 次后停在首页，残留动画回调均为 **0 次/秒**；修复前分别为 197 / 276 / 250 次/秒。 |
| 图形实现 | 内联 SVG + Canvas。十大类别各有专属几何纹样，印章与徽记均为 SVG 绘制。 |
| 字体 | 系统字体栈（宋体 / 楷体优先），不下载外部字体，离线可用。 |
| 无障碍 | 键盘可操作、跳转链接、可见焦点、语义化标签、ARIA 标注、对比度检查。 |
| 动效 | 遵守 `prefers-reduced-motion`，系统开启「减弱动效」时自动关闭动画。 |
| 浏览器 | 面向 Chrome 129 测试。 |

## 六、数据来源与统计口径

本站数据抓取自 **中国非物质文化遗产网 · 中国非物质文化遗产数字博物馆**（中华人民共和国文化和旅游部主管，中国艺术研究院主办）。

| 指标 | 官方公布 | 本站收录 |
|---|---|---|
| 国家级代表性项目 | 1,557 项 | —（不重复统计） |
| 按申报地区拆分的子项 | 3,610 条 | 3,614 条（**100% 有官方正文**） |
| 国家级代表性传承人 | 3,998 位 | 4,032 条档案记录（按姓名与编号组合去重为 3,985 条） |
| 列入联合国教科文组织名录 | 45 项 | —（未单独建页） |
| 公布批次 | 5 批 | 5 批（完整） |

**关于两个不同数字**：官方公布的「国家级代表性项目 1557 项」是**项目数**；本站收录的 3,614 条是按申报地区拆分后的**子项记录**。同一个项目若由多个地区共同申报，会拆成多行记录。例如「剪纸」是一个项目，但蔚县剪纸、扬州剪纸、傣族剪纸等地子项会分别列出。两者是不同层级的统计口径，因此本站检索使用子项数据，展示项目总数时使用官方口径，并在页脚同时标注。

**这两个数字能对上。** 官方项目编号形如 `Ⅶ-018_01_320500`，短横线前那段 `Ⅶ-018` 是项目本身的编号，后面两段才是批次与地区。把本站 3,614 条记录按编号前缀归并，恰好得到 **1,557 个不同的编号**，与官方公布的 1,557 项完全一致——也就是说，两个数字不是两套数据源，而是同一份名录的两种粒度。这个前缀也正是项目页「同一项目的其他申报地区」一节的分组依据（详见第一节）。

抓取过程中剔除了混入的其他目录数据（如「第一批国家传统工艺振兴目录」）共 383 条，其详情页标题不属于国家级非遗名录体系，已通过项目编号格式与详情页标题双重校验。

**关于传承人档案中的空缺**：4,032 条传承人记录中，3,062 条有官方编号、1,981 条标注出生日期。原始公开表格中的空缺照实留空，不作推测填补。按所属项目归集时，第五批（2021 年公布）项目所关联的 259 条档案，其编号与出生日期两栏整体未填写；其他项目批次也存在部分空缺。这里的批次来自所属项目，不是传承人的认定批次；档案记录数也不等于去重人数。

## 七、关于素材

首页与名录、传承人、技艺体验、作品墙、关于本站的栏目页头使用大都会艺术博物馆开放馆藏公版图像。每张图都链接到原始馆藏页面，统一来源清单在站内「关于素材」。原图等比缩小并转为 WebP，随成品 `media/` 目录打包，支持离线查看。

名录采用「馆藏图录」设计：纸色底、细墨线和低饱和点色，以原创器物、材料与故事意象替代大单字封面。插画表达门类或工艺主题，不作为实物照片。

十个门类分别使用书页与声纹、琴弦、飘带身段、戏冠、折扇、动作圆势、绣绷、榫卯、药臼及节气草木等图形。苏绣、宣纸、营造技艺等精选项目使用对应工艺封面，梁祝传说增加书页与蝶影；按项目编号前缀匹配，同一项目跨地区申报保持一致。插画位于 `src/components/catalog-art.js`，全部为内联 SVG，无外部图片请求，支持离线与无损缩放。

技艺体验部分的画面（绣布、纸浆、木料）同样是程序化绘制的，颜色取自真实材料的取样，而非贴图。

**三门模拟器都不是「画板」。** 苏绣给出四幅成品图纸（梅花、莲花、蝴蝶、竹子），每一格标出该用的线色与推荐针法，拖过即吸附落针，绣满后按「覆盖度 + 针法契合度」给出品级；宣纸按入帘、荡帘、出水、覆帘四道工序推进，并按荡帘的均匀程度评出匀度与品级；榫卯是**三维**的——构件按挤出体建模、按面法线做明暗、按深度排序绘制，母件沿剖切面切开，卯眼的腔体露在外面；抓住木件沿榫卯的轴向推进去，推到底即咬合，进度条实时显示推进了多少。榫卯只有一个自由度：垂直于轴的分量不产生推进——这正是它的「方向性」。插到底后还可以试「往上提」：燕尾的槽口窄、槽底宽，梯形把它锁住，提不动；直榫的槽壁是垂直的，提得动，靠的是胶与木材的摩擦。三者的成果都能导出为 PNG——图里带作品名、站点署名、日期与一方朱印，而不是一张没有出处的裸截图。

卡片突出名称和精选简介，完整显示申报单位，底部保留批次与同项目申报数；完整编号和策展问题在详情页阅读。桌面四列，窄屏逐级转为三列、两列和单列；点击或键盘 Enter 直接进入原有项目详情。项目详情页的小型门类徽记沿用原设计。`node scripts/catalog-ui-test.mjs` 验证十类封面、同源项目匹配、详情入口、SVG 标识唯一性，以及 1920/1440/834/720/390/320px 布局。

首页「门类十方」也共用这套插画，移除旧小图标与角落单字，保留实时统计数量和分类直达链接。该入口区桌面五列，手机两列，极窄屏单列；图录回归同时验证十个分类入口的封面、计数、跳转和响应式布局。

传承人列表采用纸本档案卡，以完整姓名为主视觉，分层呈现门类、编号、生年、传承项目与项目申报地区或单位。长姓名和项目名称完整换行，手机单列阅读；档案页使用同一套技艺意象插画，不作为人物肖像。统计条突出收录档案总数，出生年份中位数可直接进入年代分布。筛选、排序、分页与返回位置保持原有行为，由 `node scripts/reading-experience-test.mjs` 回归验证。

## 八、本地运行

```bash
# 安装依赖
pnpm install

# 开发预览（http://localhost:5173）；predev 会先生成详情分片
pnpm dev

# 构建：产物为 dist/index.html + dist/data/ + dist/media/，双击 index.html 即可打开
pnpm build
```

构建脚本会先把详情切成 `dist/data/detail-N.js` 分片，再把 JS、CSS 与名录等小数据内联进 `dist/index.html`，
最后自检两件事：脚本块里没有混入被误切的 HTML、分片确实落在产物里（漏了它首页正常、点进项目才空白）。

数据脚本（抓取需联网，切片与报告不需要）：

```bash
node scripts/fetch-data.mjs        # 抓取名录列表（3,614 条）
node scripts/fetch-all-details.mjs # 全量详情抓取，断点续抓（主路径）
node scripts/split-details.mjs     # 详情切片 + 传承人索引 + 首页策展名单
node scripts/coverage-report.mjs   # 离线核对覆盖率与体积
node scripts/fetch-details.mjs     # 精选详情抓取（按关键词，非主路径）
```

## 工艺原理与完成反馈

苏绣、宣纸和香山帮营造技艺的精选详情增加原创原理示意，各用三个观察环节解释针脚组织、纸帘与纤维、燕尾榫方向约束。示意标注为非真实比例，和官方项目正文分别展示。

体验页提供常驻的下一步操作提示。图纸绣满、纸帘完成捞纸流程或榫卯咬合后，会出现作品札记，集中展示本次练习指标、原理解释、保存入口与馆藏链接。自由绣没有固定完成标准，落针后即可留存。宣纸闲置时不再自动积累纸浆，湿纸纹理采用固定采样，避免成品闪烁。

`node scripts/craft-learning-test.mjs` 验证三篇专题的九幅示意、三门技艺完成与重置、结果卡导出入口，以及移动端示意排版。

体验操作补充：苏绣默认跟随图纸推荐针法，手动选择针法时退出跟随；错针按真实针法计算契合度，可拆除重绣或撤销拆除，一次拖动作为一个撤销步骤（当前页面保留最近 40 步，刷新后仍保留作品草稿）。宣纸仅在实际荡帘时积浆，静按不积浆；画布下方按钮和左右方向键也能荡帘，积浆后向上拖动、按 Enter 或点击提帘，沥水完成才可保存。配方和帘纹在开始后锁定，重新抄造可调整。榫卯支持上下方向键或按钮推进/拔出、左右方向键转视角、空格或按钮试提；自动演示和亲手拼合分别标注，重置、换型及手动接管会取消旧动画。

`node scripts/simulator-regression-test.mjs` 专门覆盖错针评价与修正、整笔撤销、静按与空帘保护、按钮完成流程、动画中重置和换型、键盘操作、试提反馈及三项目桌面/390px 排版。

三项体验均保留本机进度：苏绣同时记住是否跟随推荐针法；宣纸保留配方、帘纹、积浆和当前工序，沥水中刷新可继续；榫卯保留当前构件、视角、推进深度及是否为演示。持续操作时节流保存，离开页面前立即保存；草稿损坏时回到可操作的初始状态，存储不可用时明确提示并暂存于本次浏览。

保存和投稿共用同一份作品信息。导出前结束开场镜头并移除操作光标，投稿预览冻结作品本体，编辑标题会同步更新 PNG；手机图片中的长标题、说明自动换行，日期单独成行。纯空格标题会被拦截，提交失败可重试且复用请求编号，成功后关闭本次表单的重复提交入口。运行 `node scripts/draft-export-test.mjs` 验证跨页/刷新恢复、沥水中断、损坏草稿、存储拒绝、手机图片排版；`node scripts/works-test.mjs` 包含响应丢失后的幂等重试验证。

本页内关闭投稿弹窗后，每门技艺分别保留标题、昵称、冻结预览及提交回执；继续创作后可点击「使用最新画布」开始新投稿。提交中关闭再打开不会重复发送，切换技艺后旧响应不会覆盖当前表单；无效保存回执仍可用原请求编号重试。弹窗锁定背景滚动，关闭后恢复入口焦点，离开体验页清理暂存内容与滚动锁。填写内容仅在当前体验页暂存，不承诺刷新后恢复。

图纸、针法、丝线、榫卯构件与预设视角支持方向键循环、Home/End 首尾选择，每组仅一个 Tab 入口；自动换针、草稿恢复和选项禁用会同步键盘入口。运行 `node scripts/interaction-polish-test.mjs` 验证原生键盘操作与查询字符串容错。名录、传承人及作品墙共用查询解析，正确区分空格与加号，并保留关键词中的问号。

## 在线作品服务

已实现 Node.js + SQLite 后台，提供作品投稿、待审核列表、通过/驳回和公开作品墙。先构建前端，配置 `.env` 中的 `ADMIN_PASSWORD`（至少 12 位），再运行 `npm run server`。默认展馆地址为 `http://127.0.0.1:8787`，管理入口为 `/admin`；投稿入口在技艺练习的结果卡中。

审核后台支持下架已公开作品、将驳回作品重新送审，状态变更采用当前状态校验并保留审核记录。末页作品处理后页码会自动收敛；切换筛选或退出登录时，过期请求不会覆盖当前界面。下架内容的图片也会取消匿名访问。

作品墙可点击或用键盘打开原图，以适应窗口或实际尺寸查看，保存服务端原始 PNG。弹窗关闭后焦点回到原作品，切页会清理弹窗与滚动锁；原图每次打开重新请求，图片缺失或下架时显示提示。缩略图加载失败后可独立重试。无效技艺筛选与越界页码会整理为有效地址，异常列表响应提供重新读取入口，空分类可直接进入对应技艺。

手机导航展开后将焦点移至菜单，Tab / Shift+Tab 在菜单链接与关闭按钮之间循环，Escape 关闭后回到按钮。背景内容临时退出交互；切回桌面宽度或跳转页面后恢复。运行 `node scripts/visitor-experience-test.mjs` 验证原图查看与放大、标题转义、图片失败恢复、筛选与接口异常，以及键盘导航和屏幕尺寸切换。

管理密码、SQLite 数据库与投稿图片仅保存在本机，分别由 `.env` 和 `server-data/` 承载，均不进入 Git 或参赛包。参赛包含服务源码与 `.env.example`，接收者应自行配置密码。在线部署、持久化磁盘、备份及限制见 [后台文档](./BACKEND_PLAN.md)。

`node --test server/app.test.mjs` 验证接口与服务重启后的持久化；`node scripts/works-test.mjs` 验证浏览器投稿、审核、公开展示及离线降级。测试使用独立临时数据库，不会改动本机正式作品。
